# Как парсить LBank и MEXC

Публичного API для предиктов нет ни у LBank, ни у MEXC. Но их сайты сами берут рынки из внутреннего API,
поэтому план такой: подсмотреть эти запросы, проверить, работают ли они без браузера, и написать адаптер.

## LBank Predict

Что известно из анонсов LBank:

- предикты — это **фьючерсы** в обычном фьючерсном аккаунте: изолированная маржа, плечо до 5x, лимитные и рыночные ордера;
- цена контракта ходит от 0 до 1 USDT, то есть это и есть вероятность;
- два продукта: Prediction Futures (события) и Flash/Fast Futures (движение цены крипты за 5 минут – 4 часа);
- раздел на сайте: Futures → Prediction Market.

Отсюда следует, что YES — это лонг контракта, а NO — шорт. Стакан одного контракта даёт обе стороны:
купить NO — то же, что продать YES по bid, поэтому `no_ask = 1 − bid`. Модель `Market` уже достраивает это сама.

Пути, в порядке проверки:

1. **Публичный контрактный API** — `lbkperp.lbank.com/cfd/openApi/v1/pub/...` (`instrument`, `marketData`,
   стакан). Раз предикты живут в том же фьючерсном движке, их контракты могут оказаться в общем списке
   инструментов. Если это так, это официальный и самый стабильный путь. Проверка: `discover.py --probe-lbank`.
2. **Внутренний API страницы Prediction Market** — оттуда берутся названия событий, категории, время
   экспирации и правила. В списке инструментов публичного API их может не быть. Тогда комбинируем:
   события берём отсюда, цены — из публичного API.
3. **WebSocket фьючерсов** (`wss://lbkperpws.lbank.com/ws`) — живые цены для алертов вместо частого опроса.

## MEXC Prediction Markets

Что известно:

- отдельный Prediction-аккаунт (USDT переводится в него из кошелька);
- бинарные доли Yes/No с ценой от 0 до 1;
- на бете нулевые комиссии;
- есть Combo (до 20 событий в одном ордере, сначала только в приложении) и Up or Down (5 и 15 минут, BTC);
- в части стран раздел недоступен.

Пути, в порядке проверки:

1. **Внутренний REST веб-раздела Prediction** — основной путь. Подпись MEXC обычно требует только
   для приватных и торговых запросов, а списки рынков — простые GET.
2. **Данные, вшитые в HTML.** Если сайт отдаёт список рынков прямо в странице (`__NEXT_DATA__`
   у Next.js), хватит одного GET страницы. Разведчик проверяет это автоматически.
3. **WebSocket веб-версии** — живые цены.
4. **API мобильного приложения** — только если чего-то нет в вебе (например, Combo). Его можно снять
   через HTTP Toolkit или mitmproxy на Android, но приложения часто защищены certificate pinning.

## Разведчик эндпоинтов: `tools/discover.py`

Он открывает сайт в Chromium, записывает все JSON-ответы, данные, вшитые в HTML, и кадры WebSocket.
Затем ищет среди них списки рынков: текст вопроса, поля с ценами 0..1, ключи вроде yes/no/outcome/event.
Найденное он повторяет без браузера, чтобы понять, хватит ли простого HTTP.

```bash
pip install playwright
python -m playwright install chromium

python tools/discover.py --probe-lbank
# откроется браузер с LBank и MEXC: зайди в раздел предиктов, пощёлкай категории
# и пару рынков, потом нажми Enter в терминале
```

На Windows достаточно поставить Python (с галочкой «Add python.exe to PATH») и дважды щёлкнуть
`tools/discover-windows.bat`: он сам установит Playwright и Chromium и запустит разведчика.

Результат — `discover-out/report.md` и папка `discover-out/candidates/`. По ним пишутся адаптеры
`predicts/sources/lbank.py` и `predicts/sources/mexc.py`.

**В аккаунт не входи:** рынки видны и без него, а в записанных ответах не окажется личных данных.
Значения cookie, токенов и подписей в отчёте заменяются на `<redacted>`. В `candidates/` попадают только
ответы, похожие на списки рынков.

## Подводные камни

- **Антибот** (Cloudflare и подобные). Если в отчёте «❌ HTTP 403 — нужен браузер», варианты такие:
  повторить заголовки браузера; взять `curl_cffi`, который подделывает TLS-отпечаток Chrome;
  в крайнем случае держать Playwright и брать данные из перехваченных ответов. Это медленно, но надёжно.
- **Гео.** Предикты доступны не во всех странах. С IP из закрытого региона ответ может быть пустым или 403.
  Тогда запускай с сервера или VPN в разрешённой стране.
- **Полнота.** Страница часто грузит только «горячие» рынки. Нужно найти параметры пагинации и
  категорий, чтобы получить все.
- **Источник событий.** Стоит проверить, не берут ли биржи события у Polymarket (одинаковые
  формулировки и даты). Тогда сопоставление для арбитража будет почти точным.
- **Стабильность и правила.** Внутренние API меняются без предупреждения, а условия бирж обычно
  не одобряют автоматический сбор. Опрашивай умеренно (списки — раз в 1–2 минуты, цены — через WebSocket).
